During the live SCIM deployment, removing inventory.static caused startup to fail with "no inventory files match", despite inventory-source: managed and directory-source: scim. The workaround was to keep referencing the old inventory file containing a lone static user. That user is ignored in SCIM mode; the actual unnecessary requirement is the static file itself.

Allow a deployment using managed hosts and SCIM users to omit inventory.static entirely. Do not require a placeholder file, hosts: [], or a static bootstrap user. Authentication, user listing, certificate issuance, and administration must continue to use the SCIM directory and the existing admin-user/admin-group grants. Preserve support for optional static host/domain declarations alongside managed hosts and their existing resolution precedence.

Retain meaningful errors for explicitly configured missing or invalid static files; do not turn configuration mistakes into an empty inventory. Do not introduce a static-user fallback or change directory selection semantics.

Validate standalone inventory startup, inventory --check, and combined-server startup with no static path; verify SCIM group administration and issuance for an enrolled host. Update the SCIM and inventory guides to remove the unconditional static-file requirement. This is deferred work requested by the user; do not implement as part of the current deployment walkthrough.
