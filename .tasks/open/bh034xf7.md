Replace the current host-ID model with principal domains: the explicit SSH
authorization boundary within which a certificate for one account is
intentionally interchangeable. A domain may contain one exact host, aliases,
or an ephemeral fleet selected by inventory patterns. Domain-per-host remains
the common path and must not require a domain-centric inventory layout.

Domain identity and lifecycle:
- A domain has exactly one canonical literal value. Do not introduce separate
  human-readable `domain` and opaque `domain-id` fields.
- Human-readable domains such as `ai-worker-pool-1` are durable, explicitly
  declared inventory identities. Treat the name itself as the security
  identity: renaming creates a new domain, removing it stops issuance, and
  restoring the same name restores the same authorization domain.
- A supplied `--domain NAME` is lookup-only. Enrollment must reject an unknown
  name, preferably with a non-authoritative spelling suggestion, and must
  never create a named domain as a side effect of a typo.
- Omitting `--domain` creates a random per-host domain. Give generated values a
  reserved, self-describing namespace such as
  `epithet-host-id-v1:<base64url-random>`; reject operator-created names in the
  reserved namespace. Generated values are domains, not authentication
  secrets or a second kind of authorization primitive.
- Domain creation is a separate authenticated inventory administration
  operation. Joining an existing shared domain is an enrollment admission
  decision because it expands where domain-bound certificates are usable.

Host representation:
- Store the canonical domain literally in `/var/lib/epithet/domain` on Unix
  hosts (with native platform paths elsewhere). The file contains one value,
  not YAML or an ID/name pair; it is non-secret but must be protected from
  unauthorized modification.
- Define strict canonical parsing: accept a single bounded value and a normal
  terminal line ending, reject empty values, extra lines, control characters,
  and surrounding whitespace, and do not silently case-fold or Unicode-normalize.
- `epithet host authorized-principals` reads this file locally; target SSH
  authorization must not depend on inventory or policy availability.
- Human-readable fleet hosts contain their declared name verbatim, for example
  `ai-worker-pool-1`. Ordinary enrollment writes the reserved random value it
  generated for that exact host.

Inventory representation:
- Keep inventory host-oriented. Exact names and ordered patterns resolve to a
  domain; do not require operators to nest the common one-host domain under a
  first-class domain object.
- Add an explicit declaration list for human-readable shared domains so every
  reference can be validated at load or write time. A pattern may reference a
  declared domain; an exact host normally carries its generated domain value.
- Never require both `domain` and `domain-id`. Inventory, enrollment responses,
  the host file, audit records, and diagnostic output use the same canonical
  literal.
- Managed inventory may normalize domain records and host membership internally,
  but its API and normal list output should lead with the host or pattern and
  the readable effective domain. Opaque storage keys must not leak into the
  public model.

Principal and policy semantics:
- Update `epithet-principal-v1` to derive the SSH principal from the framed raw
  canonical domain bytes and byte-exact account name. Do not pre-hash the
  domain into a second public identity; implementations may use an internal
  hash only as a non-semantic index.
- Preserve the scheme's unambiguous SSH-string framing, bounded inputs, and
  normative interoperability vectors.
- Treat all hosts resolving to one domain as one enforcement boundary. A
  certificate obtained while requesting one member is valid on every member
  accepting that domain for the same account.
- An authorization decision must not claim a boundary narrower than the
  principal domain. Retain the requested hostname for connection routing and
  audit, but define how Writ consumes domain-wide labels/accounts so an exact
  hostname exception cannot accidentally mint a credential usable across a
  more privileged shared domain.

Enrollment and operator experience:
- `epithet host enroll --ca-url URL` creates and registers a generated per-host
  domain, then writes it to the domain file.
- `epithet host enroll --ca-url URL --domain ai-worker-pool-1` resolves the
  already-declared domain through the inventory enrollment capability,
  authorizes membership, and writes the exact name to the domain file.
- Make failures name the requested domain clearly. Never autocorrect or join a
  suggested domain without a new explicit request.
- Show readable domains prominently in inventory, enrollment, inspect, and
  audit output; generated domains remain self-identifying through their
  reserved prefix.

Migration and coordination:
- Specify a target-first migration from `/var/lib/epithet/host-id`,
  `--host-id-file`, inventory `host-id`, and the current host-ID derivation.
  Account for the short overlap during which targets may need to accept both
  old and new derived principals; do not silently reinterpret an existing
  file under new semantics.
- Incorporate the effective domain into the inventory resolver contract in
  `a5qt7g3m` before freezing that protocol.
- Reframe the generated-host registration and replacement work in `vpcj6szt`
  and `508fj5h3` around inventory host records, domain creation/membership, and
  explicit domain replacement. Coordinate the pre-1.0 principal default task
  `fcaxpp6h` with this breaking protocol change.

Acceptance:
- A host has one root-controlled literal domain file and can authorize an
  account offline using only that value and local CA trust configuration.
- A named fleet domain appears identically in its declaration, host matcher,
  enrollment command, target file, list output, and audit record.
- Misspelling a named domain during enrollment or inventory loading fails
  without creating or joining anything.
- Omitting `--domain` produces a collision-resistant value in the reserved
  generated namespace and registers it only for the intended exact host.
- Static exact hosts and patterns can both use destination-bound principals;
  patterns no longer need the globally portable account-name fallback merely
  because their members are ephemeral.
- Certificates are portable exactly within their resolved domain, and tests
  prove isolation between two different named, generated, or mixed domains.
- No public API or configuration format contains both a domain name and a
  separate domain ID for the same authorization identity.
