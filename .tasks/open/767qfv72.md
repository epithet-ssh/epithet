Security review SR-02 (medium, conditional on an endpoint returning an unsafe redirect), reviewed revision 9e53288f. Shared HTTP clients in pkg/tlsconfig/tlsconfig.go have no redirect policy. Checking the initial URL does not constrain subsequent requests. Local tests with TLS verification enabled reproduced (1) a client bearer sent to plaintext HTTP after a same-host 307 redirect; (2) GetRoot accepting a replacement SSH CA key returned over HTTP; (3) CA-to-policy forwarding the OIDC token in a redirected POST body.

Define endpoint-appropriate redirects. Reject HTTPS downgrades, constrain credential-bearing requests to the configured origin, and preserve explicit local Unix transport. Consider rejecting redirects outright for service RPC and certificate POSTs; anonymous bootstrap redirects still need an explicit safe trust rule. Apply consistent controls to OIDC discovery/JWKS/token endpoints without breaking valid separately advertised HTTPS IdP endpoints. Parse and validate schemes instead of checking case-sensitive prefixes. Cover default constructors as well as CLI-configured clients.

Reproduce: GOCACHE=/tmp/epithet-go-build-cache go test -tags securityreview -run 'TestReview(HTTPSRedirect|PolicyRedirect)' -v ./test/security. Convert probes to rejection regressions, plus supported safe redirects if any. Related older hardening task kwxdbey2; avoid retaining its obsolete httpsig assumptions. Review report: docs/security-review-2026-09-05.md.
