Continue the existing Writ follow-ups: subprocess plugins for require/when/notify, 202 pending handling in CA/client, configurable identity binding (OIDC claim to SCIM attribute), writ fmt, inventory-aware checking/lints, and extracting pkg/writ to a standalone module.

Inventory/authentication design from September 5

- Follow a5qt7g3m: CA calls inventory, then calls policy once with the original OIDC token, connection, and coherent inventory facts/revision. There is no policy-to-inventory request or extra authentication-only policy round trip. Any inventory-aware check or binding operation must respect this boundary; exact control/checking flow remains to be designed.
- CA may validate OIDC to extract the lookup identity; policy independently validates the original token and applies certificate-issuance authentication requirements. Direct inventory administration also validates OIDC, but uses inventory-owned RBAC rather than Writ. Share protocol-validation code without forcing exclusive ownership into one service.
- Keep validated authentication evidence available to policy evaluation beyond identity and expiration, including token issuance time and actual authentication time when available. OIDC iat is token issuance; auth_time is end-user authentication, and ordinary refresh is not necessarily reauthentication.
- Later define how policy can require fresh authentication even while a token remains valid, how a reauthentication-required result reaches the agent through CA, and how the agent requests actual login freshness (for example OIDC max_age). Handle absent evidence explicitly. Rule syntax, response fields/status, claim exposure, and retry behavior are open design work, not implemented by recording this plan.
- Preserve room for a concrete SAML path someday. Remain OIDC-only now; do not restore a generic authentication/plugin framework. Original credential evidence must remain available to policy rather than reducing every future mechanism to an identity string at CA.
- Static user/group names are IDs and require no separate YAML IDs. The resolver user has SCIM User shape with the enterprise extension. Managed SCIM needs persistent group-name-to-ID bindings and tombstones as recorded in 8jwaf0d8; replace the current duplicate-display-name union behavior when implementing that model. Pre-1.0 spec/implementation cleanup is welcome.
