Source: API audit thbfp6pt (.tasks/closed/thbfp6pt.md). User requested high-priority remediation tasks; filing does not implement the proposed changes.

Problem: policy returns id, certificate identity, derived principals, and authentication NotAfter, while CA already knows or derives those values, rejects conflicting values, and clamps expiry. The policy output contract overlaps CA certificate construction.

Resolve the output contract before implementing the refactor. The audit proposal is that policy returns the authorization outcome, permitted lifetime/extensions, policy content ID, and any intentionally policy-owned tighter absolute deadline; CA constructs identity and principal from trusted inventory and connection facts. This proposal is not approval to drop policy-owned constraints or change TTL/deadline semantics silently.

Acceptance:
- Document which component owns every output field, including absolute expiry versus relative TTL.
- Remove unnecessary echo/assembly behavior while preserving exactly-one requested principal, destination binding, active-user and host/account restrictions, certificate Key ID, and the verified authentication lifetime ceiling.
- Keep policy version/content ID available for private issuance audit.
- Test both account-name and destination-bound principals, denied requests, and lifetime boundaries.
- Update custom-policy API documentation and migration guidance; preserve combined and separate deployments.
