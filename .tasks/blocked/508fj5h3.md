Do not rotate or replace a host ID in place: it is immutable logical identity, not key material. A machine that needs a different host ID enrolls as a new host; the old host record is explicitly retired or revoked. Ordinary SSH host-key rotation leaves the host ID and derived principals unchanged. Acceptance: re-enrollment of an existing host preserves its ID; creating a replacement requires an explicit new-host operation; switching the target to the new ID immediately rejects certificates issued for the old host; retirement, clone conflicts, and alias reassignment remain explicit and audited.
