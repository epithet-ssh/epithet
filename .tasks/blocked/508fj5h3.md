Treat a principal-domain change as a change to the SSH authorization boundary,
not key rotation. Retiring or replacing a managed host updates its host record
and domain membership explicitly. Ordinary SSH host-key rotation leaves its
domain and derived principals unchanged. Re-enrollment without an explicit
membership change preserves the existing domain; requesting a different named
domain or a fresh generated domain requires authorized admission. Acceptance:
changing the target's domain immediately rejects certificates issued for the
old domain; host retirement, conflicting registrations, domain joins and
leaves, and alias reassignment remain explicit and audited.

Inventory ownership update (September 5): these are inventory-owned lifecycle mutations, authorized through the direct OIDC/RBAC administration boundary in 548x7rsk. Inventory records the result durably and exposes the new coherent revision to CA resolution reads; CA supplies those facts to policy. Neither inventory-to-policy nor policy-to-inventory service calls are introduced.

# Log: 2026-09-13T23:22:37Z Brian McCallister

September 13 scope: add a host-side scheduled check (cron, FreeBSD periodic, or the appropriate platform scheduler) that adopts principal-domain changes made during inventory approval or subsequent admin edits. The current enrollment command installs the reviewed domain and exits, so server edits alone do not update the target. Design trusted host identification, retrieval of the authoritative approved record, scheduler installation, and local domain replacement before implementation. Cover a domain changed while approval is pending and a later approved-record edit; unchanged checks should be idempotent, failed or untrusted reads must leave local state intact, and after adoption SSH should accept the new domain and reject the old one. The schedule, authentication mechanism, and transition behavior remain design decisions. This is deferred from the principal-domain flag and shared-domain enrollment change.
