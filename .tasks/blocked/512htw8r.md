Phase two after static inventory extraction a5qt7g3m: give the inventory service durable mutable state while retaining the same CA-mediated resolution boundary.

Start with SQLite or files on disk; choose during implementation design. Keep storage behind an inventory-owned facade so future backends do not affect policy or CA protocol semantics. No external database deployment is required for the initial version. Define coherent reads, atomic mutations, restart/crash behavior, and durability sufficient for pending enrollment, role grants, host/domain records, and one-time token consumption. Do not implement a second persistent cache merely to avoid storage reads.

Coordinate the initial dynamic milestone with existing tasks:
- 548x7rsk owns discovery, direct administrator authentication, RBAC, and configuration bootstrap for the first admin.
- vpcj6szt owns the managed host registry and principal-domain membership.
- v6hz0x82 owns pending approval and bounded/token-authorized admission.
- pmnvcb0h owns client enrollment integration.

All calls between core services originate at CA. Inventory receives resolution requests authenticated by the CA's request-bound JWT and verifies its trusted public key. Inventory never calls policy, and policy never reads the inventory backend. Direct admin requests use OIDC and inventory-owned RBAC; host requests use the admission mechanism. Keep capability permissions and resources distinct.

User/group SCIM provisioning is not part of the initial dynamic version; it is tracked in 8jwaf0d8. Continue supporting the static user configuration until a managed user source is added. The initial resolver already uses a SCIM-shaped user with enterprise extension; static names serve as IDs without extra YAML identity fields.

Acceptance: mutable inventory state survives restart; readers receive one coherent revision; storage failure remains distinct from missing entities; the storage contract supports atomic one-time-token consumption and activation without admitting pending hosts; ordinary combined deployment remains one command. Finalize dynamic freshness semantics explicitly before allowing stale reads. No particular database, HA system, or generic user-management platform is selected by this task.
