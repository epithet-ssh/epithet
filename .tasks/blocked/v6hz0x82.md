Implement one default-closed enrollment state machine for manual windows,
scoped tokens, and pluggable machine attestations. A generated per-host domain
is non-secret and never serves as proof of possession; enrollment
authentication and admission authorize the host record and its requested
principal-domain membership. Acceptance: authentication precedes admission;
manual requests allocate state only in a bounded TTL/count window; pending
entries are size-limited, deduplicated, expiring, and rate-limited; tokens are
short-lived, scoped, single-use by default, hashed at rest, and atomically
bound to one enrollment request, host record, and allowed named or generated
domain; every approval records its actor.

Agreed inventory-service boundary (September 5): this state machine lives in inventory, backed by 512htw8r. A host proves possession of its key, then either remains in pending approval (purgatory) within the existing bounded manual window or presents a valid one-time enrollment token that supplies scoped admission authority. Invalid tokens fail rather than falling back to pending. Pending records must not become eligible for certificate issuance. Approval/rejection and token creation are direct user-to-inventory operations authenticated with OIDC and authorized by inventory RBAC from 548x7rsk; bootstrap admin identity comes from configuration. Consume a token and associate/activate the authorized enrollment atomically. No policy callback or Writ administrative policy is involved. CA-authenticated resolution reads remain a separate capability.
