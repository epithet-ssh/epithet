Add direct inventory administration and host-control discovery for the initial dynamic-inventory phase, following a5qt7g3m and durable storage in 512htw8r.

Discovery

Keep --ca-url as the only host bootstrap input. GET of the CA URL continues serving the SSH CA public key and conditionally advertises one or more capability-specific inventory enrollment links only when managed dynamic inventory is configured. Static deployments omit the relation. Targets form a list from the outset; endpoint ordering, selection, and failover details remain deferred. Advertisement reflects configured capability, not backend health: an outage must fail visibly rather than silently choose unregistered static enrollment. Hosts and admin clients contact inventory directly after discovery. Policy stays private and is never advertised or used as a host-control backend.

Administrator authentication and permissions

- Inventory validates the administrator's OIDC credential and applies its own traditional RBAC: identities/groups receive roles, and roles grant permissions. Writ remains solely about certificate issuance.
- Reuse the agent/broker's existing OIDC session for administrative CLI operations. Prefer this to introducing SSH-based administrative authentication. Only the short-lived credential needed for the request may leave the broker; refresh tokens never do.
- Token validation can be shared code with CA/policy. Validate the configured issuer, expected audience/client, signature, and lifetime; token reuse must be intentional for the same Epithet OIDC client, not acceptance of an arbitrary audience.
- Bootstrap the first administrator from inventory configuration using OIDC issuer plus subject (iss, sub), not email. This must work before SCIM provisioning exists. The exact YAML shape and a helper for obtaining a pasteable identity snippet remain open UX decisions, not a committed command such as epithet identity.
- Keep permissions explicit for inspecting pending requests, approving/rejecting enrollment, creating enrollment tokens, managing hosts/domains, and reading audit data. An initial inventory-admin role may aggregate them; the exact initial role catalog and naming remain to be finalized. A CA resolution credential does not convey these permissions.
- Retain a bounded retry for ordinary token expiry as appropriate, but distinguish refresh from interactive reauthentication. Fresh authentication challenges are coordinated with 0zj196j0.

Service boundary

All calls between core services originate at CA and use request-bound JWTs verified by the CA public key. Inventory administration is a direct client-to-inventory boundary using OIDC/RBAC. Inventory must not call policy for an administrative authorization decision, and policy needs no inventory service credential. The earlier policy-to-inventory bearer-token proposal is superseded.

Acceptance: absence of enrollment links unambiguously selects local/static enrollment; managed outages do not trigger static fallback; a configured issuer/subject can administer an initially empty dynamic inventory; grants are checked per operation and approvals/token creation are audited; OIDC authentication without an administrative role cannot approve hosts; refresh tokens remain private to the broker. SCIM user/group provisioning is later work in 8jwaf0d8.
