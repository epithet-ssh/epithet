Implementation plan (design only; implementation awaits review).

Base: saved JJ change ylxkokmq/e28b23b9, feat!: normalize inventory IDs and expose agent identity. New change tulqykqz holds this plan.

Behavior and configuration

Add policy.oidc.identity-mode and --oidc-identity-mode with stable-id (default) and verified-email. Resolve an omitted mode centrally so CLI and programmatic callers agree. Keep the semantics of each mode fixed; default choice can be revisited separately.

stable-id retains existing provider defaults: sub generally, oid for configured tenant-specific Entra issuers. Keep policy.oidc.user-id-claim as a literal top-level claim override, including email. An explicit email override is permitted and does not require email_verified; it receives exactly the same nonempty-string validation as other selected claims. Document that administrators own the suitability and trust assumptions of an override, and that selecting email here deliberately forgoes the verification requirement of verified-email mode.

verified-email always reads email and requires a nonempty string plus email_verified as the JSON boolean true. Reject any user-id-claim override in this mode to avoid ambiguous settings. Reject unknown modes. Validate these combinations at startup and during --check without requiring discovery/network or additional CA settings solely for --check.

Verify signature, configured issuer, audience, expiry and nonempty sub before projecting an inventory ID. Missing, false, null or wrongly typed email_verified, and missing/empty/wrongly typed email, fail resolution. Never fall back between claims or modes. stable-id does not require email verification. Keep issuer and subject separate from the projected inventory ID.

Inventory and Writ

Keep the static inventory schema: id, userName, active, groups and attributes. In verified-email mode, id contains the exact verified email address. Preserve byte-for-byte matching; no case folding, trimming, alias handling, or domain inference. userName stays administrator-controlled and continues to supply readable certificate/audit identity. Existing inactive/unknown-user denial and duplicate checks remain in effect.

Changing modes requires explicitly updating inventory IDs and affected Writ id: selectors. Document address changes/reassignment and that email_verified is an issuer assertion of verification, not a promise of perpetual ownership or enterprise domain membership. Provide examples with identity-mode explicitly set for both modes, making the choice visible even while stable-id is the default.

Agent boundary (proposed cleanup in this change, addressing the earlier review)

Separate reusable OIDC token verification from policy-owned inventory ID projection. Remove user_id_claim from bootstrap AuthConfig and stop passing inventory mapping to the agent. epithet agent identity continues to authenticate through the running agent/cache and report verified issuer and subject, with optional oid, email and email_verified for setup diagnostics; no mapped id, bearer credentials, or arbitrary token dump. Missing/unverified email does not prevent this diagnostic command from displaying an otherwise valid identity. Document that it describes only the current user and does not certify policy acceptance or automatically identify arbitrary custom stable-ID claims. Update CLI help, IPC types, fixtures, and output documentation. Preserve cancellation, shared login, and lazy verifier caching.

Implementation sequence

1. Add shared mode/config resolution and validation, wire policy CLI/config and --check.
2. Separate token verification and inventory projection; implement both policies and strict claim handling.
3. Remove agent mapping knowledge and update the diagnostic output as proposed above.
4. Update inventory usage examples, authentication/policy/architecture docs, and migration guidance.
5. Validate focused regressions and repository checks.

Validation

Configuration tests: omitted/explicit modes, YAML/CLI/env precedence, unknown modes, forbidden combinations, --check behavior, preserved provider defaults and custom claim overrides, including an allowed email override in stable-id mode.

Validator tests: verified-email acceptance; false/missing/null/string/numeric verification rejection; invalid email types; stable-ID success without email; stable-id with an email override succeeds even when email_verified is absent or false, but still rejects missing/empty/wrongly typed email; no fallback; retained issuer/audience/signature/expiry/sub checks; exact matching.

Integration tests with the existing local OIDC fixtures: successful certificate issuance for an email inventory ID, failed issuance in verified-email mode for unverified email even with a matching record, successful issuance for that same record under an explicit stable-id email override, unknown/inactive-user denial, unchanged stable-ID/custom-claim issuance, and Writ id:/userName: behavior.

Agent tests: no mapping in discovery, credential-free diagnostic output including verification status, operation without inventory membership, retained shared-cache/cancellation semantics. Run go test -race ./pkg/broker and relevant agent identity race tests after changing this path.

Run make build, explicit go build ./cmd/epithet if make is a no-op, and make test with GOCACHE=/tmp/epithet-go-build-cache. No live-provider integration claim; tests use the local provider fixture.

Scope exclusions: signup/invites, SCIM/provisioning, Dex integration/provider expansion, directory service extraction, inventory/directory renaming, and the separate enrolled-path security issue.
