Writ currently spells a selector that matches inventory userName as id:. SCIM introduces a separate stable, non-reassignable resource id, making that spelling ambiguous. Resolve the distinction before SCIM integration and the 1.0 compatibility boundary.

Choose explicit syntax and semantics for matching the current, mutable userName versus an immutable inventory user ID. Do not assume SCIM id or externalId equals the OIDC subject: authentication binds the verified issuer/subject to an inventory record independently of Writ selectors.

Retain deliberate name-based matching: an administrator or provisioning-driven userName rename may intentionally change which name-based rules match. Group and attribute rules should continue to evaluate the bound inventory user's attributes. Preserve simple static inventory without requiring synthetic IDs merely to support future managed inventory.

Update Writ SPEC, parser/compiler/IL/evaluator behavior, diagnostics, examples, and Epithet integration together. Select the final spelling as part of this task; no replacement syntax has been agreed yet. Document migration from existing id: rules and avoid silently reinterpreting them as immutable-ID matches. Pre-1.0 compatibility is not a reason to retain confusing semantics.

Acceptance: selector meanings and rename behavior are explicit and tested; immutable-ID matches, where supported, survive renames and never adopt a replacement user solely because a name was reused; static name-based rules remain straightforward; documentation consistently separates OIDC subject, SCIM id, and userName.

Related: 8jwaf0d8 (SCIM provisioning and persistent group-name bindings), sf9zabf2 (implemented OIDC subject binding).
