Static inventory patterns and Writ host globs currently use a flat matcher in
which `*` crosses dots. That makes apparently narrow patterns such as `f*` or
`*.controlplane.internal` match names across arbitrary DNS-label boundaries.

Introduce one shared hostname-pattern language for both inventory resolution
and Writ host matching:

- Matching is anchored to the complete hostname.
- `*` matches zero or more characters within one dot-delimited label.
- `?` matches one character within one label.
- `**` is legal only as a complete label and matches zero or more labels.
- A standalone `*` remains the universal host selector.
- Doublestar's brace alternatives, character classes, escapes, path
  separators, and malformed star runs are rejected at configuration load.
- Account globs remain flat name globs and do not acquire hostname semantics.

Use `doublestar` behind a validating Epithet wrapper by translating hostname
label separators to path separators. Do not expose the dependency's broader
syntax. Invalid inventory patterns must identify their host entry; invalid
Writ patterns must produce a source-positioned compile diagnostic.

Acceptance coverage must pin single-label matching, explicit cross-label
matching, zero-label `**`, standalone universality, inventory/Writ parity, and
rejection of every unsupported doublestar metacharacter and malformed `**`.
